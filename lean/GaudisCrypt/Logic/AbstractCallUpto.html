    The up-to-bad abstract call rule (EasyCrypt's call (: bad, invP, invQ)) #

    EasyCrypt's abstract call rule has an up-to-bad form (equivF_abs_upto, src/phl/ecPhlFun.ml): the two oracle instantiations need agree only until a bad event on the right, after which the runs are unrelated except for an invariant invQ. prhlProc_abstract_call_upto (procedure with holes) and prhlProc_abstract_call_upto_module (module) are that rule.

    The coupling (prhl2_body_upto) is built by induction over the adversary's code, with the invariant uptoInv: before the bad event, the runs are synchronized as in the plain abstract call rule (syncInv: ={glob}, invP, equal locals); after it, the two runs of what remains couple independently (ProgramDenotation.prhl2.product), each side keeping a unary invariant (satisfies_inv_of_confined). An independent coupling needs both remainders to be lossless: the induction carries "this statement is lossless here" (ProgramDenotation.LosslessAt), which the adversary's losslessness gives at the start and LosslessAt.of_bind passes on to almost every intermediate state. A loop switches to the independent coupling at the start of an iteration (ProgramDenotation.prhl2.while_upto, Logic/PRHL2Upto.lean), since after the bad event the two guards need not agree.

              The up-to-bad abstract call rule (EasyCrypt's call (: bad, invP, invQ) on an abstract procedure, equivF_abs_upto in src/phl/ecPhlFun.ml), for an adversary given as a procedure with holes:

                A lossless with the two instantiations of its oracles                      (EC: `islossless A`)
  equiv[ o₁ ~ o₂ : !bad{2} ∧ ={arg} ∧ ={glob} ∧ invP
                 ==> if bad{2} then invQ else ={res} ∧ ={glob} ∧ invP ]      (per oracle)
  ∀ &2, bad{2} → hoare[ o₁ : invQ ==> invQ ]                                  (per oracle)
  ∀ &1, hoare[ o₂ : bad ∧ invQ ==> bad ∧ invQ ]                               (per oracle)
  ──────────────────────────────────────────────────────────────────────────────────────────
  equiv[ A(o₁) ~ A(o₂) : if bad{2} then invQ else ={arg} ∧ ={glob} ∧ invP
                       ==> if bad{2} then invQ else ={res} ∧ ={glob} ∧ invP ]

              bad, invP, invQ read the oracle region L (EasyCrypt rejects invariants on glob A); ={glob} is agreement on a region F containing A's footprint, outside L. EasyCrypt asks the oracles to be lossless after the bad event (its phoare … = 1); here the adversary's losslessness is asked with the two instantiations directly.
