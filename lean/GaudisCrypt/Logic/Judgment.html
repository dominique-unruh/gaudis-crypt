    Judgments about statements, generically #

    Many proof steps change only the statement of a judgment — regrouping a sequence, inlining a call — and prove the old statement equivalent to the new one, possibly along a renaming lens (StmtWithHoles.Equiv, StmtWithHoles.EquivInLens). What differs between hoareStmt, phoareStmt (and later the two sides of a relational judgment) is only how the judgment is transported along that equivalence. A JudgmentDesc records exactly that, and the steps are implemented once, for every registered judgment:

    • Judgment.onStmt — rewrite the statement with a Stmt.Equiv proof (hoare_split, …);
    • Judgment.inline (Logic/Inline.lean) — rewrite along EquivInLens, reading the conditions through the renaming.

    A judgment registers itself (registerJudgment) in a file that imports this one — the registry is an environment extension, which exists only downstream of its declaring file; Hoare triples register in Logic/TacticMisc.lean. The generic steps find the descriptor from the goal's head constant.

    structure GaudisCrypt.JudgmentDesc :
    Type

    How a judgment about one statement is transported along an equivalence of statements. A relational judgment registers one descriptor per side (side 1 and 2): what a step does to one side's statement, its transport lemmas and wp rules.

    • head : Lean.Name

      The head constant of the judgment (hoareStmt).

    • side : ℕ

      The side of a relational judgment this descriptor is about (1 or 2); 0 for a judgment about one statement.

    • stmtArg : ℕ

      The position of the statement among the head's arguments.

    • equivLemma : Lean.Name

      J … s' … → J … s … from s.Equiv s', conditions unchanged (hoareStmt_of_equiv). Its arguments are found by unification: one of type _.Equiv _ (or EquivInLens), and the judgment about s' last.

    • transportLemma : Lean.Name

      J … s' … → J … s … from s.EquivInLens s' l, with one equation (fun τ => C (l.get τ)) = C' per condition C (hoareStmt_of_equivInLens). Arguments found as for equivLemma; each equation by its type.

    • condSimp : List Lean.Name

      Simp lemmas (theorems rewritten with, definitions unfolded) run on a condition after the inliner's own cleaning, e.g. to put an expectation in the form the judgment's tactics expect.

    • condSimprocs : List Lean.Name

      Simprocs run along with condSimp.

    • postArg : ℕ

      The position of the postcondition (the condition wp steps rewrite) among the head's arguments.

    • detLemma : Option Lean.Name

      J A s (fun σ => B (upd σ)) … → J A (s; d) B … from d.Det upd (Stmt.Det): the wp rule for deterministic code, the same in every judgment. Arguments by unification, the Det proof by its type, the judgment about s last.

    • sampleLemma : Option Lean.Name

      The judgment's rule for a trailing sampling x <$ e: J A s ‹post'› … → J A (s; x <$ e) B …. Judgment-specific (∀ a ∈ support for Hoare triples, an average for phoare).

    • callLemma : Option Lean.Name

      The judgment's rule for a trailing call without a specification, if it has one (phoare: the callee's expectation, symbolically).

    • ifLemma : Option Lean.Name

      The judgment's rule for a trailing conditional that is not deterministic code (a call or a sampling in a branch), if it has one (phoare: the branches' expectations, by cases on the condition).

    • postSimp : List Lean.Name

      Simp lemmas (theorems rewritten with, definitions unfolded) and simprocs for the postcondition after each wp step: reads through writes, and whatever the judgment's conditions need.

    • postSimprocs : List Lean.Name

            Deterministic statements #

            A statement is deterministic if it maps the state by a function upd and always terminates: then its weakest precondition, for a postcondition of any kind, is the postcondition after upd. Stmt.Det d upd says this of the wp, which is all the rules use.

              def GaudisCrypt.reduceDecide :
              Lean.Meta.Simp.Simproc

              @decide p inst ↦ @decide p' inst', where p' is p simplified and inst' an instance synthesized for it, or Classical.propDecidable p' if there is none. Used by the inliner's cleaning and by every tactic's simpWithNames. Not left to simp's congruence: that re-synthesizes the instance too, and when it cannot (a condition decided classically, as open Classical in decides an equality on a type without DecidableEq) it leaves p alone, the reads in it keeping their wrappers.
