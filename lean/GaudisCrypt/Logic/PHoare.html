    Probabilistic Hoare logic #

    EasyCrypt's phoare[ c : P ==> Q ] ⋈ r (⋈ one of =, ≤, ≥): from every state satisfying P, the probability that c ends in a state satisfying Q is ⋈ r.

    The judgment is stated for an expectation g rather than an event: Stmt.ewp c g σ is the expected value of g after running c from σ, and an event Q is its indicator if Q then 1 else 0. The reason is the sequencing law phoareStmt_seq_iff, which is exact, for all three relations: the judgment about p; q is the one about p with the expectation g replaced by q.ewp g. So backwards reasoning only ever rewrites the expectation, as long as the code has an exact wp (everything but loops, including calls to abstract procedures, whose wp stays a symbolic term).

    The relation ρ is Eq, LE.le or GE.ge (the constants, not lambdas, so that rules and the printer can match on them); the bound r may depend on the initial state.

                  Loops: termination and lower bounds #

                  An upper-bound invariant cannot see that a loop terminates — a loop that never does has expectation 0, below everything.                   Lower bounds with a variant #

                  A counted loop (while (j < N)) exits with probability 0 in every round but the last, so the exit-probability argument above does not apply. A variant does: a natural number that every round strictly decreases, on every outcome of the body. Then the loop is lower-bounded by a sub-invariant by well-founded induction on the variant — the body need not even be lossless (the sub-invariant then accounts for the mass it loses).
