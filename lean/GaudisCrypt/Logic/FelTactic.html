    EasyCrypt's fel, as a tactic #

    fel cntr step q bad [pre] inv

    on a goal phoare[ P ==> bad ] ≤ r { s₀; x <- call D(O) (…); } — D a declared module, the call last (a wp first for what follows it) — applies phoareStmt_fel, EC's fel. The arguments are EC's: the counter cntr (an ℤ read off the state, §Bounder.bounder), the bound step i for a call at counter i, the number of calls q, the event bad, the oracle's precondition pre (the calls that may set bad), the invariant inv — the state-dependent ones written as the judgment's conditions (§x). What EC needs no words for is done here: the state view the conditions read (the global_vars they mention, paired into one lens L), the representation of D and its oracles' signatures (from declare module and the oracles' module type T.ext), the disjointness of D and L (fp_disjoint), the result variable x outside L.

    Goals left, in EC's order: sum (∑_{i ∈ [0, q)} step i ≤ r), init (s₀ establishes inv, ¬ bad, cntr = 0), and per oracle the premises of FelOracle: lt, step, incr, same, keep. One oracle for now (EC's [O₁: pre₁, …] with several is not needed by the SHA-3 port).
