    EasyCrypt's sp: deterministic code at the start, into the precondition #

    stmt_sp          -- EC's `sp`: on every side, as long as the first statement is deterministic
stmt_sp{i}       -- EC's `sp` on side `i` of a relational judgment
stmt_sp n        -- EC's `sp n` (`stmt_sp{i} n`): `n` statements (on each side)

    EC's sp moves the precondition forward over the assignments at the start of the code: P becomes exists x₀, P[x₀/x] /\ x = e[x₀/x]. Here, for a deterministic statement d running as the update upd (Stmt.Det d upd, assignments and the resets inlining leaves among them), the precondition A becomes fun σ => ∃ τ, A τ ∧ σ = upd τ (hoareStmt_sp, phoareStmt_sp, prhlStmt_sp_left/_right). A phoare bound is a function of the state: sp needs it unchanged by upd (a constant bound, as EC's usually are; left as a goal otherwise).

    The resets inlining leaves: not EC's statements #

    A reset (reset_vars S, the callee's locals set to their initial values) is no statement of EC's, whose inlining has none; past it the precondition is kept as it is, when the reset cannot change it (A reads none of S), and the reset forgotten — its values are never read before the callee's code assigns them.

    EC's P /\ x = e: an assignment as a read #

    For an assignment x <- e (the update upd τ = x.set (e τ) τ) that changes neither P nor e, the precondition after it is P ∧ x = e, a fact about reads (EC's), rather than the equation of states σ = upd τ: reads go through the later steps (the inliner's renamings among them).
