    The footprint of concrete code that only uses locals #

    FVP.fvP of a module is a syntactic over-approximation of what it touches. For a concrete procedure whose reads and writes are all on local variables (StmtWithHoles.LocalsOnly), it is ⊥ (FVP.fvP_proc_le_of_localsOnly): such reads and writes are zooms along localL, which is disjoint from the globals. locals_only proves LocalsOnly for a module's procedure, unfolding it as the inliner does and closing the reads and writes of local variables by rfl. What it cannot close is a read or write of a global.

    This is what makes a concrete wrapper of abstract modules (RODist(D), …) finitely supported when the abstract modules are.

    More generally, a procedure whose reads and writes touch the globals only through a lens X (StmtWithHoles.Within X) touches only X (FVP.fvP_proc_le_of_within): such reads and writes are zooms along the pair of the locals and X (ProgramState.withinL X). within_lens proves Within X as locals_only proves LocalsOnly. This is how a concrete oracle (PROM's RRO.resample) is confined to its module variable.
