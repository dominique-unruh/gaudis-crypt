    EasyCrypt's module paths: M(A, B).f #

    EasyCrypt names a procedure of an applied functor as M(A, B).f. Here that is a term:

    Preimage(A, RO).main        -- a procedure module (`Module.Proc sig`)

    where M(A₁, …, Aₙ) is Module.app M (Module.pair A₁ (… Aₙ)) and .f picks the procedure:

    • the result is of a moduletype C: .f is its accessor, C.f (Module.app M …);
    • the result is a procedure module itself (a module with a single procedure and no declared type): .f must be the name of that procedure, M.f.

    The arguments are module paths again: a name (RO), an application (Bounder(RO)), or any Lean term in parentheses ((RO.asRF sampleto m)). The head M is a name. A module that takes Lean parameters before its module parameters (module D1 (A : Adv) using (F : RO_T), so that D1 A is a module of its own, EC's partial application D1(A)) takes them first: D1(A, F) is Module.app (D1 A) F, its first arguments the head's explicit Lean parameters.

    The form exists at the term level only with the trailing .f. Without it, M(x) would also read EasyCrypt's M.f(x) of a Pr[ ] or of a procedure judgment as a module application.

    Printing: an accessor applied to a module application, and a single-procedure module applied, print in this form whenever their heads are names (ModuleApplicationSyntaxTest.lean).
