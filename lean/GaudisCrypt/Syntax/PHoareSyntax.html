    Concrete syntax for probabilistic Hoare judgments #

    The two forms of hoare[ … ] (Syntax/HoareSyntax.lean), with a relation and a bound after the bracket:

    phoare[ P ==> Q ] = r { … }             -- phoareStmt, about a statement
phoare[ M (x, y) : P ==> Q ] <= r       -- phoareProc, about a procedure

    The relation is =, <=/≤ or >=/≥. The bound r is parsed at term:max, so anything but an atom needs parentheses (= (1/2)), as in EasyCrypt; it is an ENNReal expression read like the precondition (it may mention the parameters and the globals, or for the statement form the program state).

    The postcondition Q is either an event or an expectation: a Prop is the event, and the judgment is about its indicator indicatorE Q (EC's phoare); an ENNReal expression is the expectation itself. The elaborator tries the event first. An indicator indicatorE Q prints as Q, so both round-trip.
